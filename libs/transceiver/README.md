# SI4463 RF Transceiver Driver

## Overview
This driver provides an interface for the Silicon Labs SI4463 high-performance, low-current RF transceiver. The SI4463 is a versatile sub-GHz (142-1050 MHz) transceiver chip that offers excellent sensitivity (down to -126 dBm), good output power (up to +20 dBm), and low power consumption, making it ideal for battery-powered wireless applications. Its intended usage is for APRS transceiving in our Pico Ballon Project

## Features
- SPI interface for communication with STM32U083RC
- Supports easily configuring chip with SI Labs Wirless Development Suite, see note below on configs
- Support for both polling and GPIO-based CTS signal handling

## Hardware Interface
The SI4463 communicates with the STM32 via SPI and several GPIO pins:
- SPI interface (MOSI, MISO, SCK)
- Chip Select (CS)
- Shutdown (SDN) for power-on reset
- Optionally, Clear To Send (CTS) for efficient communication

## Driver Architecture
The driver is designed to be platform-independent through the use of function pointers:
- SPI communication functions (transmit, receive, transmit/receive)
- GPIO control functions
- Delay function

The current implementation is built for STM32 HAL, but can be easily adapted for other platforms.

## Configuration Options
- `SI4463_USE_GPIO_CTS`: Define to use a GPIO pin for CTS signal instead of polling
- `BUFFER_SIZE`: Size of the internal TX and RX buffers in bytes



## Getting Started
### Initialization
```c
// Initialize configuration structure
si4463_init_t config = {
    .hspi = &hspi1,                      // SPI handle
    .transmit = HAL_SPI_Transmit,        // SPI transmit function
    .receive = HAL_SPI_Receive,          // SPI receive function
    .transmit_receive = HAL_SPI_TransmitReceive, // SPI transmit/receive function
    .delay_blocking = HAL_Delay,         // Delay function
    .timeout_ms = 100,                   // Timeout in milliseconds
    .cs_port = SPI1_CS_GPIO_Port,        // CS GPIO port
    .cs_pin = SPI1_CS_Pin,               // CS GPIO pin
    .sdn_port = SI4463_SDN_GPIO_Port,    // SDN GPIO port
    .sdn_pin = SI4463_SDN_Pin,           // SDN GPIO pin
#ifdef SI4463_USE_GPIO_CTS
    .cts_port = SI4463_CTS_GPIO_Port,    // CTS GPIO port
    .cts_pin = SI4463_CTS_Pin,           // CTS GPIO pin
#endif
};

// Initialize device structure
si4463_dev_t si4463_dev;

// Initialize the device
si4463_status_t status = si4463_init(&si4463_dev, &config);
if (status != SI4463_STATUS_SUCCESS) {
    // Handle initialization error
}
```

### Transmitting Data
```c
uint8_t data[] = "Hello, world!";
uint16_t len = strlen((char*)data);

// Transmit packet
si4463_status_t status = si4463_transmit_packet(&si4463_dev, data, len);
if (status != SI4463_STATUS_SUCCESS) {
    // Handle transmission error
}
```

### Interrupt Handling
For packets larger than 64 bytes, you'll need to handle interrupts to refill the TX FIFO during transmission:

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) {
    if (GPIO_Pin == SI4463_IRQ_Pin) {
        // Handle SI4463 interrupt
        si4463_irq_pkt_handler(&si4463_dev);
    }
}
```

## Radio Configuration
The radio configuration is defined in `radio_config.h` and is typically generated by Silicon Labs' Wireless Development Suite (WDS) tool. The configuration includes all the register settings needed to initialize the radio for the desired frequency, modulation, data rate, etc.

During development it will likely be advantageous to test various configs, which is easily supported via this librarys CMake system.

**Cmake Configuration Template**: The cmake build system uses a template file called
`radio_config.h.in` that contains a cmake configure file expression, this can be thought of as a placeholder variable that gets replaced during the configuration process. What this means is you can easily configure the driver to include a specific configuration header file without editing any of the main source code. You will see several example header files in `Inc/configs/*.h`. See this library's CMakeLists.txt file for more information.

**Adding new configs**: In order to add new configs you will need to be comfortable with SI Labs WDS Tool, and understand how the cmake configure file is working. To create a new config open WDS, select the options you are targetting, then click generate source and choose the option to save custom header file.

From there copy this file into this project by placing it under `tranceiver/Inc/configs/` and name it something descriptive. Add this file to the cmake properties lists of strings (i.e. `RADIO_CONFIG_TYPE`). In the actual `.h` file you've jsut created, you will need to delete several things that we aren't using in our project.
1. Delete this include: `#include "..\drivers\radio\Si446x\si446x_patch.h"`
2. Remove this ifdef: `#ifndef FIRMWARE_LOAD_COMPILE`
3. Delete everything after the configuration array: `#define RADIO_CONFIGURATION_DATA_ARRAY{ ... }`
4. Remove this line from the configuration data array, we've defined this patch elsewhere in the project: ` SI446X_PATCH_CMDS, \`

**Important Note**: If you configure the SI chip for a specific frequency but its not centering correctly on that frequency, that means the chip has a small error that needs to be accounted for. See the API notes for this property -> `MODEM_FREQ_OFFSET`




## Patch Support
The driver includes support for applying patches to the SI4463 chip before initialization. Patches are defined in `si4463_patch.h` and are applied during the initialization process. Never change this file!


## Limitations
- The current implementation focuses on transmit functionality, with receive functionality not yet fully implemented.
- Interrupt-driven operation for packets larger than 64 bytes is still under development.
- The driver does not yet support all advanced features of the SI4463 chip, such as frequency hopping and antenna diversity, or low power operations.
